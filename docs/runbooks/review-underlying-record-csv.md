# Review API CSV compatibility

The retained `/api/review/volume`, `/api/review/analysis`, and `/api/review/workload` endpoint families support aggregate and underlying-record CSV. These are backend compatibility contracts. For the current Analytics workspace and its exports, see [Unified analytics](unified-analytics.md).

Underlying-record CSV has one row per contributing patient report. It contains only structured, permitted values; it does not include patient names, narratives, or private clinical tables.

The API rechecks Review capability, organization, dataset, report scope, field discovery, and the expected result revision on every download. A `409` means the source changed and returns a refreshed aggregate for the caller to review before retrying. Revoked access fails validation or authorization. No export is cached. Clinical reads run in a repeatable-read database snapshot, so aggregation and contributor rows use one source version. Workload comes from one operational query. Its export reruns age buckets at the displayed observation time, which is part of the revision. The revision includes contributor identities and values as well as aggregates and freshness context.

Clinical analysis rows have `field_id`, `operation`, and `group_values_json`. That JSON array contains each displayed group contribution for the report, including the reduced value, missing/absence state, unit, selected occurrence, order mode, operational-time start/end inputs, and effective occurrence metadata. Repeated categorical values are a sorted JSON array within the group value; several occurrences do not multiply CSV report rows. Repeated numeric values are the same selected per-report reduction used by the aggregate. Custom occurrences retain definition, instance, parent, correlation, ordinal, amendment sequence, absence, and quality metadata. Operational-time values include both endpoints and an explicit valid, invalid, absent, or missing state.

Volume rows contain report ID, reporting date, and real/synthetic dataset. Workload rows contain a `review_items_json` array with every contributing item on that report, each item's result group, status, priority, criterion ID where applicable, first match and completion timestamps, historical reopening indicator, and structured exception code. A report with several review items still occupies one CSV row. An unsigned overdue draft is workload only and never appears in clinical analysis or volume.

Exports are bounded at 20,000 reports or Review items, and analysis occurrence queries have the established 20,000 row bound. Above a bound the API fails explicitly; it never emits a partial file. A stale projection also prevents clinical export. The CSV metadata names the counting unit, scope, dataset, period, and exact result revision. JSON cells are CSV escaped, and any formula-like top-level text is prefixed to prevent spreadsheet evaluation.
